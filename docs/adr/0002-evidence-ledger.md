# ADR 0002: an evidence ledger governs every published number

Status: accepted (architect, 2026-10-18). Filled in M0; implementation recorded in M3.

## Context

Numbers in READMEs and CVs drift from the code that produced them (the detector metrics in a sibling
project disagreed between the CV and the README). Hand-typed figures also lose their sample size and
uncertainty.

A second problem is specific to this project: most real findings must stay private, while a few
harmless aggregates are worth publishing. Without a single registry, the line between the two is a
matter of memory.

## Decision

Every number in documentation, dashboard copy and reports is produced by a registered claim function
returning value, n, bootstrap CI, method, caveats and a data fingerprint. Documents are templates
rendered from the claims JSON. CI fails on drift or on an unregistered number inside governed sections.
Public documents may render only allow-listed claims.

The allowlist (`strata/ledger/allowlist.py`) exists from M0 because the privacy guard enforces it on
every commit, before the ledger itself is built.

## Implementation (M3)

- **Registry.** `@claim(id, title=…, question=…, method=…, headline=…, robustness=…)` registers a
  function of a read-only warehouse context. A headline cannot be registered without a robustness
  specification, and the build refuses a headline that returns no client-level frame to test.
- **Intervals.** Percentile intervals from a client bootstrap (multinomial weights, one thousand
  resamples by default). Each claim derives its own seed from the master seed and its id, so adding
  a claim never changes another claim's interval.
- **Records.** Values carry a unit (share, difference, ratio, count, amount, p-value), the number of
  clients behind each value, caveats that may depend on the data (a caveat about an excess of
  leading nines is only written when there is one), metadata for tables, the fingerprint of the
  manifest and the software version. Values are rounded to six significant digits so files are
  stable across platforms.
- **Files.** Synthetic runs write `.strata/ledger/claims.synthetic.json`; private runs write
  `<STRATA_PRIVATE_DIR>/ledger/claims.private.json` (ADR 0008) and, with `--public`, the allow-listed
  subset to `docs/ledger/claims.public.json` after the publication rules pass. `--public` refuses to
  run on synthetic data, so the public file always holds real aggregates.
- **Templates.** `docs/findings/*.md.j2` and the README's governed section read numbers only through
  placeholders (`ledger`, `ci`, `n`, `verdict`, `mechanism`, `meta`, `rows`, `text`, `context`).
  Table row labels (age bands, digits, weekdays) come from claim metadata, never from the template.
  `raw()` exposes a value for conditions only, so interpretive sentences follow the data.
- **Check.** `strata ledger check` fails when a rendered document differs from its template's
  rendering, when a findings document has no template, when the README section drifts, when the
  public file breaks the publication rules, and when a template rendered with every placeholder
  masked still contains a digit in its prose (comments and link targets excepted).

## Publication modes (after the M4 review)

The architect fixed the allowlist after M4 with two modes. `full` claims (channel mix, the age
divide, the week, leading digits of purchases, spend concentration) are published with their
aggregates, intervals and robustness results; a value computed on fewer clients than the floor is
withheld, with its table row. `verdict_only` headlines (`silence_by_channel`) are published as a
`PublishedVerdict` record in the public ledger's `verdicts` list: the verdict, the stratifier names,
the stratifiers that reverse the effect and a number-free explanation, generated by the robustness
checker next to the full one. The renderer answers only verdict placeholders for such a claim, so
a template cannot print one of its numbers, and `ledger_violations` (used by the build, the check
and the commit guard) refuses any other field or any digit in its words.

## Alternatives considered

- **Numbers in notebooks, copied into documents.** The status quo that produced the drift.
- **Generated documents without a check.** Rendering is not enough: a hand edit to a rendered file,
  or a hand-typed number next to a placeholder, must fail CI.
- **Publishing everything with differential privacy.** Considered for the twin (ADR 0004); for
  findings, a short allowlist of coarse aggregates is simpler to reason about and to audit.

## Consequences

Writing docs requires registering claims first, which is slower and far more honest. The dashboard
and the report share one source. Private claims never leave the machine. Templates cannot even type
a digit in prose, which occasionally forces a definition into claim metadata; that friction is the
point.
